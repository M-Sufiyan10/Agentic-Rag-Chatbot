# M4 MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At startup the agent loads extra tools from MCP servers listed in a config file. One is a custom FastMCP server in this repo (`mcp-utils`: weather, unit conversion, time-zone conversion), which runs as its own service. The other is the third-party `fetch` server, which reads a web page by URL. A server that is down never stops the app.

**Architecture:**

- **`mcp-utils/`** is a separate uv project, a FastMCP server over streamable HTTP on port 8100, with a Dockerfile and a compose service.
- **The backend** reads `backend/mcp_servers.json` and uses `langchain-mcp-adapters`' `MultiServerMCPClient` to load each server's tools in the lifespan. One server at a time, with a timeout; a failure is logged and that server skipped. The loaded tools are added after the built-ins.
- **Tool calls** each open their own short MCP session (the adapters' default stateless mode), so a restarted server keeps working without restarting the app.
- **Guards:** every MCP tool is wrapped by a guard that turns exceptions and timeouts into an `"Error: …"` string, keeping M2's "no tool raises" contract.

**Tech Stack:** `mcp` Python SDK (FastMCP), `langchain-mcp-adapters` 0.3.x, `mcp-server-fetch` pinned to **2026.10.24** and run via `uvx`, `httpx`, `pint` (unit conversion), Open-Meteo (keyless).

## Global Constraints

- **Keyless.** Nothing needs an API key. Weather comes from Open-Meteo: geocoding at `https://geocoding-api.open-meteo.com/v1/search`, forecast at `https://api.open-meteo.com/v1/forecast`.
- **No filesystem MCP server.** The `fetch` server must not be given `--allow-private-ips`. Verified while planning: v2026.10.24 refuses private, loopback and link-local addresses on every request and every redirect hop by default. A backend test asserts the committed config never passes that flag.
- **Pinned server.** `fetch` runs as `uvx --from mcp-server-fetch==2026.10.24 mcp-server-fetch`.
- **The app works with MCP down.** A server that can't be reached at startup is skipped with a WARNING log naming it, and startup continues. A tool call to a server that has since died returns an `"Error: …"` string within `MCP_TOOL_TIMEOUT_SECONDS` (default **30**).
- **Tool names are unique.** An MCP tool whose name equals a built-in tool's name (`calculator`, `current_datetime`, `web_search`, `search_documents`) or an already-loaded MCP tool's name is skipped with a WARNING log. Built-ins always win.
- **Config is data, not code.** `MCP_CONFIG_PATH` defaults to `mcp_servers.json`, resolved relative to the backend directory (anchored to the `backend/` folder, not the CWD). A missing file means no MCP servers (INFO log). Invalid JSON or an unknown transport is a startup error with a clear message. Supported transports are `streamable_http` (needs `url`) and `stdio` (needs `command`, optional `args`).
- **`mcp-utils`** listens on `MCP_UTILS_HOST` (default `127.0.0.1`; the Docker image sets `0.0.0.0`) and `MCP_UTILS_PORT` (default `8100`), at path `/mcp`.
- **SSE contract is unchanged.** MCP tools produce ordinary `tool_start`/`tool_end` events.
- **Tests never hit the network.** `mcp-utils` tests use `httpx.MockTransport`. Backend MCP tests launch a tiny stdio test server with `sys.executable`.
- **Checks:** backend `ruff check`, `ruff format --check`, `mypy app` and `pytest`; `mcp-utils` `ruff check`, `ruff format --check`, `mypy` (strict) and `pytest`; frontend `lint` (0 errors), `typecheck` and `test`. All pass. CI gains an `mcp-utils` job.

## Review Focus

1. **`mcp-utils` isn't running when the backend starts** (the most common dev case). The app starts, the built-in and `fetch` tools work, and the log says which server was skipped (Task 2 test).
2. **An MCP server hangs or dies mid-conversation.** The tool returns an `"Error: …"` string within the timeout and the model answers anyway (Task 2 test with a slow tool and a crashing tool).
3. **"Fetch http://localhost:5433" or "http://169.254.169.254/".** The fetch server refuses, the model reports it, and nothing internal is read (Task 2 config test, plus a Task 4 live check).
4. **Weather for a place that doesn't exist ("Atlantis"), or Open-Meteo is down.** A readable `"Error: …"` naming the place (Task 1 test).
5. **Nonsense conversions ("5 kg to metres", "5 parsecs to bananas").** `convert_units` returns "Error: can't convert kilogram to meter" or "Error: unknown unit 'bananas'" instead of raising (Task 1 test).

**Interfaces (produces):**

- `server.py`: `mcp = FastMCP("mcp-utils", ...)` with three tools. Each returns `str` and never raises (`"Error: …"` on failure). Docstrings tell the model when to use them.
  - **`get_weather(location: str) -> str`**
    1. Geocode with `name=<location>&count=1`. No result → `"Error: couldn't find a place called '<location>'."`
    2. Fetch the forecast with `current=temperature_2m,apparent_temperature,relative_humidity_2m,wind_speed_10m,weather_code` and `timezone=auto`.
    3. Return `"<Name>, <Country>: <description>, <t>°C (feels like <a>°C), humidity <h>%, wind <w> km/h (as of <local time>)."`. The WMO code is mapped to a short description in a dict.
    4. HTTP or network errors → `"Error: the weather service is unavailable right now."`
  - **`convert_units(value: float, from_unit: str, to_unit: str) -> str`**
    - Uses `pint`; temperatures use offset-aware conversion.
    - Returns `"<value> <from> = <result rounded to 6 significant digits> <to>"`.
    - Unknown unit → `"Error: unknown unit '<u>'."`. Incompatible dimensions → `"Error: can't convert <from> to <to>."`
  - **`convert_time(time: str, from_timezone: str, to_timezone: str) -> str`**
    - `time` is ISO 8601 (`2026-11-11T15:00` or `15:00`, the latter meaning today in `from_timezone`).
    - Returns `"<ISO in from tz> (<from>) = <ISO in to tz> (<to>, <weekday>)"`.
    - Unknown zone → `"Error: unknown timezone '<z>'. Use an IANA name like 'Asia/Karachi'."`. Unparseable time → `"Error: couldn't read the time '<t>'. Use ISO format like 2026-11-11T15:00."`
- Test seam: `weather.py` builds its client through a module-level `make_client() -> httpx.AsyncClient`, with a 10 s timeout, that tests monkeypatch to use `httpx.MockTransport`.
- `__main__.py` runs `mcp` with transport `streamable-http` on `MCP_UTILS_HOST`/`MCP_UTILS_PORT` at path `/mcp`. `--stdio` runs over stdio instead, for local debugging.
- Dockerfile: `python:3.12-slim` plus uv. Copy the lockfile and sync with `--frozen --no-dev`, run as a non-root user, set `MCP_UTILS_HOST=0.0.0.0`, `EXPOSE 8100`, `CMD ["uv","run","--no-dev","python","-m","mcp_utils"]`.

### Task 2: Backend MCP client

**Files:**

- Create: `backend/app/agent/mcp.py`, `backend/mcp_servers.json`, `backend/tests/agent/test_mcp.py`, `backend/tests/mcp_servers/echo_server.py` (the stdio test server)
- Modify: `backend/pyproject.toml` (`uv add langchain-mcp-adapters`), `backend/app/config.py` (`mcp_config_path: str = "mcp_servers.json"`, `mcp_tool_timeout_seconds: float = 30`, `mcp_startup_timeout_seconds: float = 20`), `backend/app/main.py`, `.env.example`

**Interfaces:**

- **`mcp_servers.json`** (committed):
  ```json
  {
    "utils": {
      "transport": "streamable_http",
      "url": "http://localhost:8100/mcp"
    },
    "fetch": {
      "transport": "stdio",
      "command": "uvx",
      "args": ["--from", "mcp-server-fetch==2026.10.24", "mcp-server-fetch"]
    }
  }
  ```
- **`load_mcp_config(path: Path) -> dict[str, dict[str, Any]]`**
  - Validates each entry: a known transport plus its required keys, and string args.
  - Raises `ValueError(f"Invalid MCP config {path}: …")`. A missing file returns `{}`.
  - Relative `path`s resolve against the backend directory: `Path(__file__).resolve().parents[2]`.
- **`async def load_mcp_tools(connections, *, reserved_names: set[str], tool_timeout: float, startup_timeout: float) -> tuple[list[BaseTool], dict[str, str]]`**
  - For each server, in config order: `await asyncio.wait_for(MultiServerMCPClient({name: conn}).get_tools(), startup_timeout)`.
  - Any exception or timeout → WARNING `"MCP server %r unavailable, skipping: %s"`, and status `"unavailable"`. Otherwise status `"ok"`.
  - Skip and WARN on name collisions with `reserved_names` or an earlier MCP tool.
  - Wrap each kept tool with `guard_mcp_tool`.
  - Returns `(tools, {server: status})`.
- **`guard_mcp_tool(tool: BaseTool, *, server: str, timeout: float) -> BaseTool`**
  - Returns a tool with the same `name`, `description` and `args_schema` whose call is `asyncio.wait_for(tool.ainvoke(args), timeout)`.
  - Timeout → `f"Error: the {server} tool server didn't respond in {timeout:g}s."`
  - Any other exception → `f"Error: the {server} tool server failed ({exc})."`
  - A `ToolException` / tool error result from the server passes through as its text.
- **`main.py` lifespan:** when the `tools` seam is `None`, build the built-ins, then `load_mcp_tools(load_mcp_config(settings.mcp_config_path), reserved_names={t.name for t in builtins}, ...)`, and pass `builtins + mcp_tools` to `build_graph`. Store the statuses in `app.state.mcp_servers`.
- **`/api/health`** returns `{"status": "ok", "mcp": {server: status}}` (empty dict when MCP is unused).
- **`tests/mcp_servers/echo_server.py`:** a FastMCP stdio server with three tools: `shout(text) -> text.upper()`, `boom() -> raises RuntimeError("kaboom")` and `nap(seconds: float) -> sleeps`.

- [ ] **Step 1: Write the failing tests** (`test_mcp.py`):

    - The committed `mcp_servers.json` loads, has servers `utils` and `fetch`, and the `fetch` args contain `"mcp-server-fetch==2026.10.24"` and **do not contain `"--allow-private-ips"`**.
    - A missing file → `{}`.
    - Bad JSON or `{"x": {"transport": "carrier-pigeon"}}` → `ValueError` mentioning the path.
  - **Loading** (stdio echo server via `sys.executable`):
    - The tools include `shout`, the status is `{"echo": "ok"}`, and `await shout.ainvoke({"text": "hi"}) == "HI"` (compare the content text).

  - **Collisions:** `reserved_names={"shout"}` → `shout` is skipped and a warning is logged.
