# Agentic Chatbot — Milestone Roadmap

**Spec:** `docs/superpowers/specs/2026-11-10-agentic-chatbot-design.md`

The spec covers several subsystems, so it is built as seven milestones. Each milestone gets its own plan, and each plan produces a working, testable app. A plan is written only when the previous milestone is merged, so it is based on the real code rather than guesses.

| #   | Milestone               | Delivers                                                                                                                                                                            | Plan                             |
| --- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| M1  | Foundation & thin slice | Postgres, auth (register/login/refresh), conversations, streamed chat with a LangGraph agent (no tools yet), React UI, CI                                                           | `2026-11-10-m1-foundation.md`    |
| M2  | Agent tools             | Tool loop in the graph; `calculator`, `current_datetime`, `web_search` (DuckDuckGo); `tool_start`/`tool_end` SSE events + tool-status chips; max-iterations guard; history trimming | `2026-11-11-m2-agent-tools.md`   |
| M3  | Documents & RAG         | Upload (PDF/DOCX/TXT/MD), background ingestion into pgvector, per-user `search_documents` tool, citations event + UI, documents panel, `reindex` command                            | `2026-11-11-m3-documents-rag.md` |
| M4  | MCP                     | Custom FastMCP `mcp-utils` server (weather/time zones/conversions) as its own service, `fetch` server, `langchain-mcp-adapters` client loaded from config                           | later                            |

## Decisions made while planning, binding on all milestones

- **Chat history lives in the LangGraph checkpointer.** There is no separate messages table. History is trimmed when the model is called and never deleted from state, so the UI can always read the full transcript from the graph state.
- **SSE event contract.** Each event is `event: <name>` plus `data: <json>`. Later milestones add events but never change existing ones.
  - `token` → `{"text": str}`
  - `tool_start` → `{"id": str, "name": str, "input": object}` (M2)
  - `tool_end` → `{"id": str, "name": str, "output": str}`, with output truncated to 500 characters (M2)
  - `citations` → `{"items": [{"document_id": str, "filename": str, "chunk_index": int, "snippet": str}]}` (M3)
  - `done` → `{"content": str}`
  - `error` → `{"message": str}`
- **Cross-user access returns 404, not 403**, so the API never confirms another user's resource exists.
- **npm instead of pnpm.** pnpm isn't installed, and this avoids an extra tool for visitors. This changes the spec's tooling row; it's Claude's call.
- **Compose Postgres listens on host port 5433**, because 5432 is already used by a local Postgres on the dev machine.

## Carried forward from the M1 reviews

Each later milestone's plan must pick these up.

- **M2:**
  - Disallow or proxy markdown images in `MessageBubble`. `web_search` is the first source of untrusted text reaching the model, and an image URL can leak data. (done in M2)
  - Filter `token` events by `metadata["langgraph_node"]` once the graph has more than one LLM call. (done in M2)
  - `DELETE` a conversation returns 409 while a reply is in progress. (done in M2)
  - Move `get_graph` to a deps module. (done in M2)
  - State in the plan exactly what happens to graph state when a run fails partway or the client disconnects. In M1, a client disconnect still leaves an unanswered user message; fix it with the same `RemoveMessage` rollback under `asyncio.shield`. (done in M2)
- **M7:**
  - Refuse to start with the default or a short `JWT_SECRET` when `COOKIE_SECURE=true`.
  - Use a constant-time login (dummy argon2 verify for unknown emails).
  - Consider revoking refresh tokens.
  - Use an absolute CI badge URL once the repo has a remote.
  - Turn on the `setup-uv` cache and add a `push` branch filter in CI.
- **Low-priority cleanups (any time):**
  - Anchor Alembic paths to the file location and set `compare_type=True`.
  - Add tests for malformed JWT claims, the remaining `get_current_user` branches, nonexistent ids and messages over 8000 characters.
  - Validate the provider up front in `build_chat_model`.
  - Frontend:
    - type-guard SSE payloads
    - add an `AbortController` when the user navigates away
    - keep the typed text when creating a chat fails
    - show sidebar rename/delete errors
    - move `useAuth` into its own file to clear the lint warning
